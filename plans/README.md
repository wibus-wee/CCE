## Direction roadmap (007–009)

Plans 007–009 are one sequenced evolution — **ranker → world model** —
anchored on the v6.0 adversarial-benchmark evidence
(`false_positive_rate` 0.60, `decoy_hit_rate@20` 0.282,
`symbol_recall@20` ≈ .52) and the v6 A/B finding that the four legacy
structural priors are approximations of one propagation mechanism:

1. **007 — Earn the mechanism.** Query-seeded propagation replaces the
   hand-tuned priors it subsumes, proven by parity on the 51-case
   adversarial set. Prerequisite for everything below.
2. **008 — Evidence semantics.** Propagation emits typed evidence
   *paths*, not just mass: principled abstention (the only honest
   answer to FPR 0.60 — RRF scores are cross-query incomparable and
   cannot be thresholded), symbol-level claim support, and same-name
   disambiguation.
3. **009 — World-model surface.** The typed graph becomes a product
   surface: structural operators (`type:symbol`, `kind:`, `pat:`),
   source→sink dataflow as constrained propagation (dataflow view
   `Partial` → `Ready`), and gateway fan-out federation across workers.

Deliberately deferred (rejected sequencing): SPLADE-Code vocabulary
bridge (fixes recall, not abstention — sequence after 008), K8s/auth
(service layer is already ahead of kernel maturity — don't scale
untrusted answers), larger embedding models (measured flat in the 004
ladder).

## Follow-up work intentionally not planned yet

- **SCIP importer** (report Phase 0A, `origin=Scip/Compiler` producers):
  schema ready (`relation.rs:37-39`); call edges sit at 0.6 / type refs at
  0.55 because resolution is spelling-based (`relations.rs:295-361`).
  Report §22.2 predicts its largest long-term value is training supervision,
  not rank boost. Sequence after 005 lands so its effect on
  Task→Component/impact intents is measurable. This is the next
  engineering-sized design task (indexer choice per language, SCIP
  symbol→region mapping, external-tool provenance).
- **Atlas evaluation surface** (`map`/`explain`/`impact` cases): requires a
  new case capability field, adapter dispatch to those subcommands, output
  normalizers, and entity/edge-level metrics — a design task, not dataset
  authoring. Sequence after 003/005 land.
- **ToCS-style synthetic architecture generator** (report §17.1/§16.2):
  programmatically generated repos with planted component graphs +
  constraints give uncontestable L0 Hard Gold — the only way to measure real
  component-boundary F1. Larger effort; revisit after L3 clustering exists
  to have something to evaluate.
- **L3 component inference** (report §5.3 affinity formula): deliberately
  out of scope per `docs/architecture.md:54` until the deterministic layer
  is verified — i.e., after SCIP + landmarks land. `ChangedWith` co-change
  edges already persist (`relations.rs:484+`), so most affinity inputs
  (call/import/type/co-change/build/path) exist; only `semantic` weight is
  missing.
- **L2 exploration-process + L4 task-outcome eval** (report §14.3/§14.5):
  WrongTurnRate, time-to-first-correct-component, Pass@1 deltas — all need
  a real agent loop + trajectory recording (dead `trajectories` table). Needs
  a product decision — record on every query? opt-in flag? — before a build
  plan.
- **`engine.rs` split** (1528 lines; `index()` inlines ~6 view
  materializations): justified, but zero user-facing value alone — bundle
  it with the SCIP pass, which adds another materialization anyway.
- **`trace_feature` / `locate_task` APIs** (report §A): the report's
  Feature-Flow endpoint; blocked on 006-class landmarks + L3 components.
- **Web UI wiring for `/v1/map|explain|impact`**: real gap (`api.ts` only
  uses index/status/context) but it's feature work downstream of the atlas
  eval surface; not a blocker for the measurement sequence.

## Findings considered and rejected

- **Bigger embedding first** (e.g. jumping straight to e5-base/4B+): the
  report explicitly recommends `0.6B zero-shot → task SFT → larger ablation`
  and calls framework landmarks "比更大 embedding 更重要的结构补丁".
  Plan 004 therefore tests a ladder including Qwen3-Embedding-0.6B, and 006
  is sequenced as a first-class alternative lever, not an afterthought.
- **Daemon thin-client / CLI batch mode for ONNX cold start**: partially
  addressed by 001 (`engine_latency_ms` separates session init from engine
  compute). A full daemon-client CLI rework is not worth it until the
  measurement shows per-case session init actually dominates runtimes.
- **Dropping `trajectories`/`invalidations` tables**: premature — GC already
  references `trajectories`; decide keep-vs-drop together with the flywheel
  decision above.
- **`query_ms` semantics change**: rejected — wall-clock subprocess time is
  honest end-to-end cost; `engine_latency_ms` (001) is additive instead.
- **Silver-label-only eval** (report §15 warning): the v5 dataset stays
  maintainer-annotated Hard Gold; do not let LLM-generated architecture
  labels become the sole eval gold — silver labels are training data, not
  the measuring stick.
